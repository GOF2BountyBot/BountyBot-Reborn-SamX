# T8 — Activation-rule modules: cloak + booster + thruster

Wire three activation-rule modules into the tick resolver: HP-threshold cloak,
HP-threshold booster (with distance push + accuracy debuff), and passive
thruster ramp. T4 has already shipped the pure accuracy functions; T8 supplies
the per-tick activation state that feeds them.

## Spec references

- §5 — accuracy surfaces these modules feed (cloak REPLACE override; booster
  debuff `effect_pct × BOOSTER_ACCURACY_DEBUFF_FACTOR`; thruster ramp
  `effect_pct × THRUSTER_ACCURACY_BONUS_FACTOR × ramp`). All three are

- §10 — Built-in U'tool supersession; `effective_cloak = equipped if

## Deliverables

### Combatant module state (shared scaffolding)

Per-combatant, per-module-instance runtime state covering the three classes
addressed here:

- `cooldown_remaining_ms: int`
- `effect_remaining_ms: int`
- `activation_count: int`
- `last_threshold_crossed_pct: list[int]` (or a set) — records which threshold
  values for THIS combatant have already been consumed, so the universal
  trigger rule's "missed threshold = skipped, no retry" (§8) holds.

**Initial state at tick 0 (§8):** `cooldown_remaining_ms = 0`,
`effect_remaining_ms = 0`, `activation_count = 0`, `last_threshold_crossed_pct
= []`. Module is "ready to fire on first qualifying threshold crossing
without warmup delay."

**HP-percent tracking:** each combatant tracks its own HP-percent across
ticks. Threshold crossings are detected at phase 5 using *post-damage* HP
(Appendix B). A threshold is *crossed* when the previous-tick HP-percent was
above the threshold and the current post-damage HP-percent is at or below it.
The threshold is consumed at crossing regardless of whether the device
actually activates — the universal rule says missed = skipped, no retry.

**HP-percent definition** (locked in §8 — "HP-percent definition" paragraph): the percent is sum-of-layers / sum-of-maxes:

```
hp_percent = (current_shield + current_armour + current_hull)
           / (shield_max + armour_max + hull_max)
```

Ships without shield modules have `shield_max = 0` and the formula degrades naturally. Use this exact form for both cloak and booster threshold detection.

### Cloak module (§7.2 + §10)

Trigger evaluation at phase 5 (own combatant):

- Crossing detected against `CLOAK_HP_THRESHOLDS_PCT` ([66, 33]).
- Eligible iff: `cooldown_remaining_ms <= 0` AND `activation_count < 2` AND
  `effect_remaining_ms == 0` AND the crossed threshold is not in
  `last_threshold_crossed_pct`.
- On activation:
  - `effect_remaining_ms = effective_cloak.effect_duration_ms`
    (U'tool=10000ms, Sight Suppressor II=20000ms, Shadow Ninja=40000ms —
    sourced from the module's seed `extra_atts`).
  - `activation_count += 1`.
  - Append the crossed threshold pct to `last_threshold_crossed_pct`.
  - Emit `module_activation` event with `data = {module: "<class>",
    trigger_hp_pct: <threshold_value>}` per §12. **`trigger_hp_pct` is the
    configured threshold value (66 or 33), NOT the actual HP-percent at
    crossing — LOCKED (Q4).**

Per-tick mechanics (run on every phase 1/5):

- **Effect tick-down (phase 1 alongside cooldowns):** while
  `effect_remaining_ms > 0`, `effect_remaining_ms -= TICK_MS`.
- **Cooldown starts at effect EXPIRY** (§7.2): on the tick where
  `effect_remaining_ms` transitions from `> 0` to `<= 0`, set
  `cooldown_remaining_ms = effective_cloak.loading_speed_ms`.
- **Cooldown tick-down:** while `cooldown_remaining_ms > 0`,
  `cooldown_remaining_ms -= TICK_MS`. On transition from `> 0` to `<= 0`,
  emit `cooldown_end` (consistent with T5/T7's cooldown semantics).

Effect on accuracy (§5 / §7.2): while own cloak active
(`effect_remaining_ms > 0`), opponent's `pilot_primary_acc` and
`pilot_turret_acc` are REPLACED by `clamp(CLOAK_SET_VALUE,
ACCURACY_CLAMP_MIN, ACCURACY_CLAMP_MAX)`. T4 already implements the REPLACE
branch; T8 wires the "is opponent's cloak active" boolean and exposes
`effective_cloak` to T4's lookup.

**Universal trigger rule (§8):** if the threshold crosses while
`cooldown_remaining_ms > 0` OR `effect_remaining_ms > 0`, the threshold is
consumed (added to `last_threshold_crossed_pct`) but `activation_count` does
NOT increment and no `module_activation` is emitted. The threshold is NOT
retried later.

**Built-in U'tool supersession (§10):**
```
effective_cloak = equipped if has_equipped else builtin
```
- If `ShipLoadout` has an equipped `CloakModule`, use it; built-in is
  bypassed entirely.
- Else if `ship.builtinModules` contains `"U'tool"` (Scimitar, Specter),
  synthesize a virtual U'tool instance with its wiki stats and treat it as
  the active cloak. The built-in is off-slot (does not consume
  `max_modules`) — that is a loadout-builder concern, not T8's. T8 just
  reads `builtinModules` from the ship config.
- If neither: combatant has no cloak; phase-5 cloak evaluation no-ops.

**Unique-equip assumption (§10):** at most one cloak instance per
combatant. Defensive stance against malformed loadouts: first-wins on
multiple equipped instances. Do NOT validate equip rules — that is the
loadout-builder's job.

### Booster module (§7.3)

Trigger evaluation at phase 5 (own combatant):

- Crossing detected against `BOOSTER_HP_THRESHOLDS_PCT` ([80, 60, 40, 20]).
- Eligible iff: `cooldown_remaining_ms <= 0` AND `activation_count < 4` AND
  `effect_remaining_ms == 0` AND the crossed threshold is not in
  `last_threshold_crossed_pct`.
- On activation: same shape as cloak — set `effect_remaining_ms`, increment
  `activation_count`, consume threshold, emit `module_activation` with
  `data = {module, trigger_hp_pct}`.

**Two simultaneous effects while active (§7.3):**

1. **Distance push at phase 6 (§2 / Appendix B).** While the booster is
   active, passive closure is **suspended** — replaced (not added to) by
   the per-tick push delta:
   ```
   push_delta_m = BASE_SHIP_SPEED_MPS × (effect_pct / 100) × (TICK_MS / 1000)
   ```
   `current_distance += push_delta_m` each tick of the boost window. After
   expiry, normal passive closure resumes. There is no `MAX_DISTANCE_M`
   cap — distance is naturally bounded by per-module `effect_pct ×
   duration_ms` and the 4-activation cap.
2. **Opponent accuracy debuff (§5).** While own booster is active, expose
   `(effect_pct, active=True)` to T4's `compute_pilot_accuracy()` so the
   opponent's accuracy is reduced by `debuff_pp = effect_pct ×
   BOOSTER_ACCURACY_DEBUFF_FACTOR`. T4 already does the subtraction and
   clamp; T8 wires the "is opponent's booster active and what's its
   `effect_pct`" lookup.

Cooldown semantics, tick-down, and `cooldown_end` event behave identically
to cloak. Cooldown starts at effect expiry (§7.3).

**Universal trigger rule (§8):** identical to cloak — threshold consumed
even when blocked by cooldown or active effect; not retried.

**Booster-user can still fire (§7.3):** accepted simplification. Phase-3
fire evaluation is NOT suppressed during own boost. No code change in
phase 3 — the booster activation only affects phase 6 (distance) and the
accuracy lookup the opponent reads.

**Unique-equip (§10):** same defensive stance as cloak.

### Thruster module (§7.4)

- **Passive — always active when conditions permit (§7.4 / §8).** No
  HP-threshold gating, no `duration_ms`, no cooldown, no toggle, no
  activation event.
- **Distance gate is the only gate** (§5 / §7.4): the ramp is a function of
  `current_distance` and is naturally 0 outside `THRUSTER_WINDOW_M` (750 m).
  T4's `thruster_ramp(current_distance)` already handles the geometry.
- **T8 work:** expose a per-combatant "is thruster equipped, what's its
  `effect_pct`" lookup so T4's `compute_pilot_accuracy(primaries=True, ...)`
  can apply `bonus_pp = effect_pct × THRUSTER_ACCURACY_BONUS_FACTOR × ramp`.
- **No `module_activation` event for thruster (§12 explicit).** Passive
  modules emit nothing.
- **Primaries only (§7.4).** T4 already excludes thruster from
  `pilot_turret_acc`. T8 just confirms the lookup path stays
  primary-exclusive.
- **Unique-equip (§10):** same defensive stance.

## Test surface (max 2 mocks per test)

Cloak:
- **Activation at 66 %:** combatant drops from 100 % to 65 % in one tick →
  cloak activates that tick, emits `module_activation` with
  `trigger_hp_pct = 66`, opponent's next-tick `pilot_primary_acc` ==
  `clamp(CLOAK_SET_VALUE, ...)`.
- **Activation at 33 %:** second activation; `activation_count == 2`.
- **Third activation blocked:** another threshold-like crossing after 33 % →
  no activation; `activation_count` capped at 2.
- **Skipped while cooling:** threshold crosses while
  `cooldown_remaining_ms > 0` → no activation; threshold consumed; never
  retried after cooldown ends.
- **Cooldown starts at effect expiry:** U'tool (10 s effect + N ms cooldown).
  First activation at t=0; `effect_remaining_ms` decrements to 0 at t=10 s;
  cooldown starts at t=10 s; ready again at t=10 s + `loading_speed_ms`.
- **Accuracy override during cloak:** while own cloak active, opponent's
  `pilot_primary_acc` AND `pilot_turret_acc` both → `clamp(CLOAK_SET_VALUE,
  ...)`.
- **Built-in supersession — no equipped cloak:** Scimitar with no equipped
  cloak → built-in U'tool functions with 10 s / its cooldown.
- **Built-in supersession — equipped wins:** Scimitar with equipped Shadow
  Ninja → Shadow Ninja's 40 s duration used; built-in U'tool bypassed.

Booster:
- **Activation at 80 %:** distance push observable in `current_distance`
  delta per tick during the boost window; opponent accuracy debuff
  observable in opponent's `pilot_primary_acc`.
- **Four activations:** thresholds 80 / 60 / 40 / 20 all crossed across a
  long fight → `activation_count == 4`.
- **Fifth blocked:** if a fifth threshold-like crossing happens (shouldn't,
  given the threshold list, but exercise the `activation_count < 4` guard)
  → no activation.
- **Passive closure suspended during boost:** during the boost window,
  `current_distance` increases (or holds) per `BASE_SHIP_SPEED_MPS ×
  (effect_pct / 100) × (TICK_MS / 1000)` per tick. After expiry, normal
  300 m/s closure resumes.
- **Firer can still fire during boost:** weapon fire evaluation in phase 3
  is NOT suppressed for the booster user.

Thruster:
- **Passive ramp:** combatant at 500 m with Pendular (`effect_pct = 40`,
  k=0.1) → `pilot_primary_acc` includes the ramped bonus per the §5
  formula; combatant at 1000 m → bonus = 0; combatant at 300 m → bonus =
  max.
- **No event:** thruster equipped, combatant closes from 1000 m to 500 m —
  NO `module_activation` event emitted at any point.
- **Turret exclusion:** `pilot_turret_acc` does NOT include thruster bonus
  even when thruster is "active" (distance < 750 m).

Cross-cutting:
- **Universal trigger rule — cooldown overrides threshold:** cloak fires at
  66 %; before cooldown ends, HP crosses 33 % → 33 % consumed but no
  activation; after cooldown ends, even if HP is now well below 33 %, the
  threshold is NOT retroactively triggered.
- **HP-percent computation:** `(shield + armour + hull) / (shield_max + armour_max + hull_max)` per §8. Pin specific layer combinations (e.g. shield exhausted but armour+hull intact → percent reflects only the surviving layers).
- **Initial state at tick 0:** all activation modules ready
  (`cooldown_remaining_ms = 0`, `effect_remaining_ms = 0`,
  `activation_count = 0`); first qualifying threshold crossing fires
  immediately.

## Risks and notes

- **HP-percent formula is locked in §8:** `(shield + armour + hull) / (shield_max + armour_max + hull_max)`. Apply uniformly; do not introduce per-module variants.
- **Threshold detection is on CROSSING, not `==`** (§8). HP must transition
  *across* the threshold within a single phase-5 evaluation. If HP starts
  below a threshold (Phase-2 damaged-start), the threshold is NOT
  retroactively triggered. Phase-1 always starts at 100 %, so all
  thresholds are crossable.
- **Cooldown starts at EFFECT EXPIRY, not at activation** (§7.2 / §7.3 /
  §8). Easy mistake. The cooldown timer engages on the tick where
  `effect_remaining_ms` transitions to <= 0, not on the tick of activation.
- **Booster distance push REPLACES passive closure** (§2 / §7.3) during
  the boost window. Don't apply both; passive closure is suspended.
- **Built-in cloak is off-slot** (§7.2 / §10) — does not consume
  `max_modules`. Loadout-builder concern, not T8's. T8 reads
  `builtinModules` directly from the ship config.
- **Supersession is canonical:** `effective_cloak = equipped if
  has_equipped else builtin` (§10). Do NOT stack; do NOT check built-in
  when an equipped cloak is present.
- **"Missed threshold = skipped, no retry" (§8).** Once a threshold has
  been crossed (whether or not it triggered), it is consumed. Do NOT
  re-evaluate the same threshold after cooldown ends.
- **Thruster passive — no activation event** (§12 explicit). Do NOT emit
  `module_activation` for thruster.
- **Thruster primaries-only** (§5 / §7.4 / §6.3). Turrets and rockets are
  unaffected.
- **`module_activation` payload `trigger_hp_pct`** uses the threshold value
  itself (config knob entry), not the actual post-damage HP-percent —
  **LOCKED (Q4); no spec-author confirmation outstanding.**
  (T10 stat counting reads only `module` from the payload, so either
  interpretation would work for Phase-1, but the configured-threshold value
  is the locked choice for log consumers.)
- **Loadout contract (§10):** T8 trusts the baked `ShipLoadout`. Multiple
  cloaks / boosters / thrusters → first-wins. Do NOT validate equip rules
  in the resolver.
- **Phase-2 deferred modules** (ShieldInjector, RepairBeam,
  TransfusionBeam) are loaded for fidelity per §7.10 but do NOT activate.
  T8 does not touch them.
